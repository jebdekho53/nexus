# Matrix trial and device access

Policy confirmed by owner: 48 hours or three distinct successful PNRs, whichever comes first. Existing valid paid keys continue independently; after trial expiry/exhaustion, purchase a seller/admin-issued paid key.

Trial state and server time are authoritative. The desktop collects salted/namespaced hashes of SMBIOS UUID, useful baseboard serial and Windows MachineGuid; raw identifiers are not uploaded. The trial hardware identity is collected independently of cached matrix-device files and Windows user/RDP session names. Detected VMs and unavailable/generic hardware IDs require a seller key. This reduces ordinary profile/reinstall/RDP abuse; it is not hardware attestation. Spoofed firmware, cloned/undetected VMs and patched client software cannot be proven genuine by these hashes. MAC addresses are intentionally not used as the primary identity.

An online check precedes each trial login/start. One server reservation at a time prevents parallel runs on the same trial/device. The actual booking actor hook captures PNR completion. Quota deduplication uses HMAC-digested PNRs. At the owner's request, a separate admin-only booking history now stores the PNR and allowlisted IRCTC username/journey metadata. Public trial status omits those records. Pending client reports are OS-encrypted and reconciled before another booking. Unknown/crashed payment outcomes retain their reservation rather than automatically granting more trial attempts. An already authorized payment may finish and display its PNR after trial expiry. No existing paid key, signing secret or customer data is replaced.

Important limit: PNR completion is reported by the desktop, not independently authenticated with IRCTC. A fully modified client can lie about hardware/outcomes or remove local gates; absolute abuse prevention would require provider-side verified booking receipts/another trusted execution boundary. Do not claim this feature is unbreachable. Developer/source mode remains key-free by design and is not a protected commercial trial distribution.

Activation/verification captures the server-observed public IP with first/last seen times and ten recent IPs per device. Only explicitly trusted reverse proxies may supply forwarded IPs. VPN/proxy exits are not a physical location or a reliable person/device identity. Admin key lists expose device access history; seller/customer license responses do not expose it. Trial IPs/counts are available only through authenticated /api/admin/trials.

Server modules: trials.cjs, client-address.cjs, existing licensing/hierarchy adapters. Persistent trials.json resides beside registry.json; it must be backed up and preserved across deployments. Never delete it to refresh a release. The proxy allowlist is configuration (trusted-proxies.json or MATRIX_TRUSTED_PROXIES), not client input.

Desktop entry point: activation window offers an explicit free-trial button and explains device/IP collection. Trial status is shown on controller/tools pages. Runtime f2082 guards booking actor entry, including controller bulk paths, and f2233 records final PNR. Trial support requires the new desktop release; existing installers do not acquire the new client flow just from a server update.
